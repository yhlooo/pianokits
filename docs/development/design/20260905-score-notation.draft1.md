## 1. 背景与目标

### 1.1 问题

当前 M1 记谱（`src/core/midi/quantize.ts`）以 **C4（MIDI 60）为硬分界**，把合并后的全部音符
一刀切成「upper/lower」两个谱表。由此产生三类观感错误：

1. **分谱表不符合演奏实态**：MIDI 文件通常一轨一个声部（钢琴曲常见左手/右手各一轨）。
   按 C4 硬切会把「左手和弦里跨 C4 的低音 + 高音」劈到两个谱表，谱表归属失真。
2. **音轨信息被丢弃**：`parse.ts` 把多轨合并成单事件流后，量化器无法再按轨分组，
   只能靠音高猜。
3. **单谱表单声部**：每只手内部所有音符被压成一个 voice（重叠事件被强行收紧），
   丢失「旋律 + 伴奏」「持续低音 + 走动声部」的复调。

### 1.2 目标（本设计）

1. **分谱表以 MIDI 音轨为准**：MIDI 里有几轨（非打击乐、非空），谱子就有几个谱表；
   每个谱表是高音谱还是低音谱，由该轨的音高分布决定（不再用全局 C4 一刀切）。
2. 在上述基础上，落实 R-记谱 §4.3 提出的记谱质量改进：自适应量化、谱表内复调分声部、
   连音（三连音）检测、`@tonaljs` 拼写、踏板延音、按拍符杠。

### 1.3 非目标（本设计不做）

- 出版级排版、谱面/音符编辑、移调、导出 MusicXML（M3 再做）；
- 打击乐轨记谱（继续排除打击乐轨）；
- tempo/拍号**检测**（本设计只使用 MIDI 元数据，缺失时兜底；无元数据的拍速估计列入后续）。

## 3. 数据模型变更

### 3.1 领域模型（core/model.ts）

新增踏板事件，供量化延长 note 结束（`Note` 结构不变，仍带 `trackIndex`）：

```ts
/** CC64 延音踏板事件（value > 0 为踩下，0 为抬起） */
interface SustainEvent {
  time: number // 秒
  value: number // 0~127
}

interface Song {
  // …既有字段不变…
  /** 延音踏板事件（CC64，合并所有轨、按 time 排序），M1 未采集，本设计新增 */
  sustainEvents: SustainEvent[]
}
```

`parse.ts` 变更：从 `track.controlChanges[64]` 读取踏板事件，归一化为秒级 `SustainEvent[]`。

### 3.2 记谱中间模型（quantize.ts 输出，ScoreModel 重构）

```ts
type Clef = 'treble' | 'bass'

interface ScoreStaff {
  /** 来源 MIDI 轨道序号（对应 Song.tracks） */
  trackIndex: number
  /** 轨道名（可空，展示用） */
  name: string
  /** 由轨内音高分布决定 */
  clef: Clef
}

interface ScoreModel {
  ppq: number
  durationSec: number
  measures: Measure[]
  /** 谱表列表（一轨一谱表），数组下标即 staffIndex */
  staffs: ScoreStaff[]
  /** 扁平化事件流，供播放高亮比对 */
  events: NotatedEvent[]
  displayKeysig: { sf: number; mi: 0 | 1 }
}

interface NotatedEvent {
  id: number
  onsetSec: number
  endSec: number
  /** 指向 ScoreModel.staffs 下标（取代 M1 的 'upper' | 'lower'） */
  staffIndex: number
  /** 谱表内声部序号（0 起，主声部=0） */
  voiceIndex: number
  measureIndex: number
  /** 小节内起始拍 */
  beatOffset: number
  /** rest 时为空 */
  keys: ScoreKey[]
  rest: boolean
  /** 延音线连接的时值片段（≥1） */
  pieces: ScorePiece[]
}
```

要点：

- `staff: 'upper' | 'lower'` → `staffIndex` + `staffs[]`，`ScoreView` 据此画任意数量谱表。
- 新增 `voiceIndex`：谱表内多声部（主声部 0，副声部 1……），渲染时对应 VexFlow 的
  `Voice`，副声部用反向符干区分。
- `Measure`、`ScorePiece`、`ScoreKey` 结构不变（见 D-M1 §6.6 / 现有源码）。

## 4. 分谱表规则（本设计的核心）

### 4.1 轨 → 谱表映射

输入 `Song`，输出 `ScoreStaff[]`：

1. 过滤：跳过 `Track.percussion === true` 与 `noteCount === 0` 的轨；
2. 排序：其余轨按文件原始 `index` 升序；
3. 映射：每轨一个 `ScoreStaff`，`trackIndex` 取轨序号，`name` 取轨名。

谱表数量 = 通过过滤的轨数。`Song.notes` 按 `trackIndex` 归入对应 `staffIndex`（
`trackIndex → staffIndex` 建立一一映射）。

### 4.2 谱号判定（音高分布）

对每轨独立判定，规则即「**主要音区高于 C4 → treble，主要音区低于 C4 → bass**」：

```
weightedMedian(track.notes):
  按 pitch 升序，累计 (end - start) 时长权重，
  取累计权重恰好越过总时长一半处的 pitch
clef = weightedMedian >= 60 ? 'treble' : 'bass'
```

- 「主要高于/低于 C4」用**时长加权中位数**度量：累计时长过半的音高落在 C4 之上即 treble；
- 选**中位数**而非均值：对个别极端高低音稳健；选**时长加权**：短暂经过的低音/高音不应翻转谱号；
- **两轨时**：该规则自然产生「音区较高的一轨 = 高音谱、较低的一轨 = 低音谱」（对应钢琴左右手分轨）；
- **多于两轨时**：逐轨套用同一规则，主要高于 C4 的轨标 treble、主要低于 C4 的轨标 bass。

### 4.3 边界情况与处理

| 情况                     | 处理                                                                                                                                                                                      |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 单轨文件（含左右手混排） | 按规则得**单谱表 + 单谱号**；音域过宽时谱表会拥挤。**已决策：不做「单轨大谱表」特例**——适用钢琴的 MIDI 一般已按左右手分轨，单轨混排属少数情况，接受其观感并保持「一轨一谱表」规则的纯粹性 |
| 多轨（如 4~16 轨乐队曲） | 严格一轨一谱表，系统 = 全部谱表纵向堆叠 + 左侧 bracket 分组；轨过多时谱面很长，接受之（参考谱定位）                                                                                       |
| 轨内既有左手也有右手     | 靠 4.2 谱号 + §5.3 复调分声部在**同一谱表**内用多声部呈现，不再跨谱表拆分                                                                                                                 |
| 打击乐轨                 | 继续排除，不产生谱表                                                                                                                                                                      |

## 5. 量化管线（M2 算法）

输入 `Song`，输出 `ScoreModel`。在 M1 基础上替换/新增如下环节（顺序即流水线）：

### 5.1 拍点/网格

1. 拍速曲线、小节划分：沿用现有 `buildBeatCurve` / `buildMeasures`（基于 MIDI tempo/拍号元数据，
   缺省 120 / 4-4），逻辑不变。
2. **网格生成（自适应）**：基础网格步长可配置，默认 **1/16**（`GRID_STEP = 0.25`）；
   另生成一套 **三连音网格**（把每拍三等分）供连音检测使用。

### 5.2 量化（吸附）

替代 M1 的「就近四舍五入到 1/8」：

1. 对每个 note 的起止，枚举「基础网格」与「三连音网格」上的候选点；
2. 计算代价 `cost = |Δt|（时间误差） + λ·complexity（罕见时值的罚项）`，取最小者；
3. 起止吸附后时长圆整到合法时值，跨拍/跨小节拆分 + 延音线连接（沿用 M1 的
   `decomposeBeats`，扩展支持附点与更小时值）。

> λ 与罚项表是可调参数，目标是「宁可用常见时值略牺牲时间精度，也不产出三十二分音符碎片」。

### 5.3 谱表内复调分声部

在「一轨一谱表」之上，每谱表内再做多声部（默认最多 2）：

1. **和弦合并**：同轨内（量化后）起音相同的音符合并为一个和弦（单声部内的和弦）；
2. **声部分配**（贪心 + 重叠检测）：
   - 事件按 onset 排序处理；主声部（voice 0）优先；
   - 若事件与主声部当前事件**在时间上重叠**，且与主声部音区差距明显，则进入副声部（voice 1）；
   - 副声部同样按「不重叠」继续；超过 `MAX_VOICES` 时并入最近声部（按音高距离）；
   - `MAX_VOICES` 默认 2，遇到重叠线条更多的复杂轨可**放宽**（上限 4，作为可调参数）。
3. 输出每个事件带 `voiceIndex`。

作用：右手「旋律 + 伴奏」、左手「持续低音 + 走动声部」不再被压平。

### 5.4 连音（三连音）检测

1. 对每个小节，按拍取未匹配的短时值音符序列；
2. 用「二等分 vs 三等分」两套网格拟合：分别计算每组音符 onset 与两套网格的总误差；
3. 三等分拟合显著更优（误差低于阈值）且成组为 3 的整数倍时，标记为三连音
   （渲染时用 VexFlow `Tuplet`，时值比例 3:2）。

> M2 先覆盖最常见的三连音；五连音/六连音等复杂连音列为后续。

### 5.5 音高拼写（@tonaljs）

替代手写 `spellPitch`：

1. 对每个音高，用 `@tonaljs/note` 从 MIDI 号枚举候选拼写（`note.fromMidi` 及升/降等价拼写）；
2. 按三要素打分，取最优：
   - **调号一致**：候选是否落在 `@tonaljs/key` 的 `majorKey(sf)` / `minorKey(sf)` 音阶内；
   - **和声上下文**：与同时间点的其它音构成的自然音程/和弦更受偏爱（`@tonaljs/pcset` 集合归属）；
   - **旋律走向**：与前后音的音级距离，级进优于跳进。
3. 输出 `{ letter, accidental, octave }`（`ScoreKey` 结构不变，`accidental` 允许 `##`/`bb` 扩展）。

### 5.6 踏板延音

1. 量化前，用 `Song.sustainEvents` 延长音符结束：一个 note 在踏板踩下期间，结束延长到
   「下一个同音高的 note-on」或「踏板抬起」，二者取先到者（参考 Magenta
   `applySustainControlChanges` 的语义）；
2. 延长后再进入 §5.2 量化，避免长音被切碎成休止符。

### 5.7 符杠与休止符

- **符杠**：小节内按拍分组，每个拍组内连续的八分/十六分音符用 `Beam` 组合（替代 M1 的
  `Beam.generateBeams` 全量组合）；声部内分组，不跨声部；
- **休止符**：每声部独立折叠空隙为休止符，合并为尽量大的合法时值（沿用 `mergeRestPieces`
  思路，按声部分别处理）。

## 6. 渲染端变更（ui/score-view.ts）

1. **多谱表**：每个 `ScoreStaff` 画一个 `Stave`，`addClef(staff.clef)`；系统 = 本行所有
   谱表纵向堆叠，用 `StaveConnector` 分组——2 谱表用 `brace`（钢琴大谱表观感），>2 谱表
   用 `bracket`（乐队系统观感）。
2. **多声部**：每谱表按 `voiceIndex` 建 `Voice`，副声部 `setStemDirection` 反向；
   `Formatter.joinVoices` 处理同谱表多声部对齐。
3. **布局**：系统高度 = `staffs.length × STAFF_GAP + 上下留白`；`measuresPerSystem`、
   懒加载、播放高亮（`eventSystem` 按 `staffIndex` 定位）沿用现有机制，仅把
   `'upper'/'lower'` 分支改为按 `staffIndex` 迭代。
4. **轨道名**：可选在谱表左端显示 `ScoreStaff.name`（乐器名/轨名），钢琴曲通常为空则省略。

### 7.2 测试

- **谱表映射**：两轨（各含上下行音高）→ 两个谱表、谱号分别 treble/bass；
- **谱号判定**：单轨音高集中在上方 → treble；集中在下方 → bass；时长加权中位数抗离群；
- **复调分声部**：同轨内重叠的高低两条线 → 两个 voice、副声部反向符干；
- **三连音**：三个等时值音符落在一拍内 → 识别为三连音；
- **拼写**：G 大调 F♯/F♮、F 大调 B♭/B♮ 等沿用现有 `spellPitch` 测试并扩展到和声上下文用例；
- **踏板**：踏板踩住期间的长音不被切成休止符；
- **回归**：现有 `quantize.test.ts` 中「跨拍拆分、跨小节断开、和弦合并、网格吸附」继续通过
  （仅「以 C4 为界分左右手」用例改为「按轨分谱表」）。

## 8. 分阶段实施计划

| 步骤 | 内容                                                                                      | 验收                                      |
| ---- | ----------------------------------------------------------------------------------------- | ----------------------------------------- |
| 1    | `parse.ts` 采集 CC64 → `Song.sustainEvents`；`model.ts` 加 `SustainEvent`                 | 解析含踏板的 MIDI 后 `sustainEvents` 非空 |
| 2    | `quantize.ts` 重构分谱表：按 `trackIndex` 分组 + 谱号判定，输出 `staffs[]` + `staffIndex` | 双轨文件产生两谱表、谱号正确（单测通过）  |
| 3    | `score-view.ts` 多谱表渲染（brace/bracket、多 clef）                                      | 双轨/多轨文件正确画出多谱表               |
| 4    | 谱表内复调分声部（`voiceIndex` + 多 Voice 渲染）                                          | 重叠双线分两个声部                        |
| 5    | 自适应量化（1/16 网格 + 代价吸附）+ 三连音检测                                            | 十六分/三连音可读性提升（单测 + 手测）    |
| 6    | 引入 `@tonaljs` 拼写 + 踏板延长                                                           | 拼写单测扩展通过；长音不碎                |
| 7    | 按拍符杠 + 每声部休止符合并                                                               | 典型钢琴曲观感明显改善                    |

> 步骤 1~~3 是「分谱表按轨」的最小闭环（可独立交付）；4~~7 是质量改进，可逐步推进。

## 9. 风险与缓解

| 风险                                                            | 缓解                                                                              |
| --------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| 单轨含左右手时，一轨一谱表 + 单谱号音域过宽、观感不如原 C4 拆分 | 明确为已知取舍；可选「单轨大谱表」缓解（§10 Q1）；后续可评估                      |
| 多轨（乐队曲）谱表过多、页面很长                                | 参考谱定位，接受；后续可加「轨勾选」隐藏部分谱表（D-M1 M2 已列轨道勾选）          |
| 复调分声部/三连音/拼写启发式仍可能出错（转录本质难题）          | 参数可调 + 单元测试 + 明确「参考谱」定位；不上出版级承诺                          |
| `@tonaljs` 多子包依赖面                                         | 按需引子包（note/key/pcset），避免引全集                                          |
| 重构破坏现有高亮/滚动                                           | `ScoreModel` 字段兼容迁移（`staff`→`staffIndex`），高亮逻辑按新索引重写并回归测试 |

## 10. 待讨论问题（Q）

1. **多轨谱表是否显示轨名**：钢琴曲轨名常为空/无意义，是否默认隐藏、仅乐队曲显示？
   （默认倾向：2 轨钢琴曲隐藏轨名；>2 轨时在谱表左端显示轨名以区分声部。）
