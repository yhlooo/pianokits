# 设计：瀑布流配色改为“按轨着色”五色循环

- 日期：2026-09-05

## 1. 目标与范围

### 1.1 目标

把瀑布流音符条与琴键点亮的颜色语义从“**按手**（以 C4 音高为界的两色）”改为“**按轨**（一轨一色，五色循环，第 6 轨复用第 1 色）”，其余观感与行为不变。

### 1.2 范围

- **仅瀑布流视图**：音符条渐变色、对应发光色、琴键点亮色；
- 五线谱仍按记谱惯例以 C4 分大谱表（`quantize.ts`）——那是记谱排版惯例，与本次“可视化配色”无关，**不变**；
- 解析、领域模型、播放、调度、存储、样式 token 全部**不变**。

### 1.3 非目标（本次不做）

- 轨道图例、轨道勾选列表（原计划在 M2 的轨道勾选落地时一并做图例）；
- 色觉无障碍的“第二编码”（纹理/描边，见 §4.3）；
- 调整判定线光带、五线谱高亮、全局 accent 体系。

## 2. 背景与动机

- **现状**：`src/ui/waterfall-view.ts` 用 `HAND_SPLIT_PITCH = 60` 按音高把音符切成“右手琥珀 / 左手钢蓝”两色（`RH_TOP/RH_BOTTOM`、`LH_TOP/LH_BOTTOM`），琴键点亮跟随手色。
- **调查结论（R-分手 §1、§4）**：MIDI 文件不含“手”信息；“按音高分左右手”本质是把演奏惯例当事实——交叉手、双手跨越音区时必然标错。文件里唯一可靠的、与“来源分组”对应的维度是**轨道**（领域模型 `Note.trackIndex`，0 基，见 `src/core/midi/parse.ts`）。
- **决策（2026-09-05 用户确认方向）**：**只分轨不分手**——瀑布流按轨道着色；5 种相互和谐的颜色作为色池，每轨一色，第 6 轨循环用第 1 色。
- **过渡友好**：多数钢琴 MIDI 恰好两轨一高一低（例如《梦中的婚礼》：轨 0 高音区、轨 1 低音区），按轨着色后轨 0 = 琥珀、轨 1 = 钢蓝，观感与旧版几乎一致。

## 3. 设计方案

### 3.1 颜色分配规则

- `colorIndex = note.trackIndex % 5`，色板为 `TRACK_COLORS[colorIndex]`；
- 轨道号为 0 基（`Note.trackIndex` 即 0 基 MIDI 轨道号）；用户所说的“第 6 轨”即 `trackIndex = 5` → `5 % 5 = 0` → 复用第 1 色，与规则一致；
- 打击乐轨音符本就不进 `Song.notes`（`parse.ts` 已过滤），不影响配色；
- **已知取舍**：Format 1 常见第 0 轨是指挥轨（只有 tempo/拍号、无音符），此时第 1 色可能闲置。默认**按原始 `trackIndex` 着色**（“轨道号 ↔ 颜色号”可预测，用户看到的轨道顺序即颜色顺序），不压缩编号；备选方案见 §6 Q1。

### 3.2 五色色板（推荐值）

> 色板延续“乌木舞台上被照亮的宝石”气质：十档颜色全部压在窄明度带内（顶 66–69%、底 47–53%），
> 饱和度克制（冷色更低以补偿其视觉重量），色相全环分布、相邻最小间隔 37°，同屏和谐且可区分。
> 已按 HSL 数值校验，见文末附注。

- 色相（顶色 HSL）：37° / 212° / 100° / 169° / 256°，相邻最小间隔 37°；
- 明度：顶 66–69%，底 47–53%；与乌木底（`#121110`）的明度差 ≥ 47，五色均清晰可辨；
- 饱和度：26–68%（琥珀略高以匹配暖色的自然显亮，丁香/鼠尾草最低，冷色更“安静”）；
- 第 1、2 色保留现有两色，保证最常见的“双轨钢琴 MIDI”零视觉跳变。

### 3.3 音符条渲染（改动最小化）

- 渐变顶/底、力度→明度映射（`vf = 0.55 + 0.5 × velocity/127`）、力度→透明度（`alpha = 0.55 + 0.45 × v`）、顶部 1px 高光、圆角**全部保留**，仅颜色来源从“手色”换成“轨色”；
- 音符条阴影色改为对应轨色：`rgba(轨色顶, 0.45)`，blur 6 不变；
- **判定线光带保持 accent 琥珀**（它表达“此刻的判定”，与轨色无关）。

### 3.4 琴键点亮

- 颜色跟随“当前正在该键上发声（`playhead ∈ [start, end)`）的音符”所属**轨色**；同键多音符时取**最近 onset** 者；
- 释放后 80ms 渐隐不变；
- 实现：现有“按 2 色分两批绘制”改为**按轨色分批绘制**（批次数 ≤ 5，每批复用现有 `paint(entries, color)` 结构）；活动键每帧不超过十几个，性能无虞。

### 3.5 代码影响点

- 新建 `src/ui/track-colors.ts`：导出
  `TRACK_COLORS`（5 项 `[顶色, 底色]` 的 RGB 三元组数组）与 `trackColor(trackIndex)`（内部取模）——
  单一色板来源，供瀑布流与未来轨道图例/五线谱复用；
- `src/ui/waterfall-view.ts`：
  - 删除 `HAND_SPLIT_PITCH`、`RH_TOP/RH_BOTTOM/LH_TOP/LH_BOTTOM`；
  - `drawNotes` 用 `trackColor(n.trackIndex)` 取色，`right` 分支删除；
  - `drawActiveKeys` 改为按轨色分批（§3.4）；
- 其余文件（`parse.ts`、`model.ts`、`quantize.ts`、`score-view.ts`、`transport.ts`、`style.css`）**不改**。

### 4.2 与“克制用色”原则的关系

风格指南原则 1“克制用色”针对**装饰与状态色**；瀑布流音符色是**数据编码**（轨道类别 → 色相）。五色已压到同一明度/饱和度带内，且瀑布流是唯一使用该多色域的区域；判定线、琴键外框、主按钮、选中态等仍只使用 accent 琥珀。五线谱视图完全不受影响。

### 4.3 色觉辅助说明（如实记录）

低饱和多色相在色觉障碍下，相邻色对（琥珀↔鼠尾草、钢蓝↔丁香）区分度会下降。缓解：色相间距已 ≥ 37°；颜色是辅助编码，轨道身份可经 M2 的轨道列表确认。“色相 + 第二编码（纹理/描边）”留待 M2 轨道图例时评估，本次不做。

## 5. 验收标准

1. 加载《梦中的婚礼》（2 轨）：轨 0 = 琥珀、轨 1 = 钢蓝，观感与旧版一致；
2. 构造（或导入）≥ 6 条含音符轨道的文件：前 5 轨依次为五色，第 6 轨颜色与第 1 轨相同；
3. 力度明暗映射、顶部高光、判定线光带、琴键点亮与 80ms 渐隐行为不变；
4. 琴键点亮色 = 发声音符所属轨色（同键多音符取最近 onset）；
5. 五线谱观感与旧版无差异；
6. 类型检查与现有测试（transport / quantize）全绿。
