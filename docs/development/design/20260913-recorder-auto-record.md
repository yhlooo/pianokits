# 设计：录音工具的演奏自动录制（自动开始 / 静默自动暂停 + 空音轨提示）

- 日期：2026-09-13
- 状态：**正式生效（2026-09-13 实现）**
- 前置设计：`docs/development/design/20260912-midi-recorder.md`（录音工具主设计；本文档扩展其
  §3.3 控制器、§3.4 视图、§3.5 按钮语义、§6 验证）
- 关联设计：`docs/development/design/20260913-recorder-pedals.md`（踏板录制；本文档的静默判定与
  `pedalDown` / `heldPedals` 状态打交道）
- 影响文档：`docs/usage/`、`README.md` 属面向用户的文档，按 AGENTS.md 口径本次不直接修改
  （需用户侧补充"演奏即录、静默 3 秒自动暂停、空音轨中央提示"说明）

## 1. 需求

| #   | 需求                                                                                 | 落地口径                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | 未播放也未录制的状态下，按 MIDI 键盘任意键开始录制                                   | 空闲（`mode === 'idle'`）且键盘已连接时收到 **Note On** → 走与点录制按钮同一条开始路径；这一次按下就是本次录制的第一个音符（§3.1）                                        |
| R2  | 这种自动开始的录制，连续 3s 没有键盘输入就暂停录制                                   | 自动录制期间每 25ms 检查 `position - lastInputAt >= AUTO_PAUSE_SEC`（3s）→ 与手动暂停同一条收尾路径（§3.1）                                                               |
| R3  | 自动暂停不影响手动启动的录制，手动启动的录制需要手动暂停                             | 只有**由演奏开始**的那一次录制带着 `autoRecord` 标记走静默看门狗；`toggleRecord()` 开始的那一次永远不看（§3.1）                                                           |
| R4  | 自动开始的录制也可以手动暂停                                                         | 两种录制共用 `finishRecording()`，`toggleRecord()` 不区分来源                                                                                                             |
| R5  | 自动开始录制 / 自动暂停录制时，录制按钮像手动录制一样切换录制 / 暂停图标             | 复用既有的 `RecorderUiState.mode` 回调（`recording` → ⏸、`idle` → ●），控制器在开始/暂停处照常 `emitState()`，视图侧零改动（§3.2）                                        |
| R6  | 未播放也未曾录制（全空音轨）时，在音轨正中央显示「在 MIDI 键盘上演奏可自动开始录制」 | 音轨舞台中央的 DOM 浮层 `.recorder__hint`；显示条件 = `mode === 'idle' && !hasContent`。录了一部分再暂停后 `hasContent` 为真 → 不显示；「结束」清空后重新显示             |
| R7  | （2026-09-13 追加）未连接 MIDI 键盘时，同一处改为提示「未连接 MIDI 键盘」            | 同一个中央提示浮层按状态换文案（`centerHintText()`）：未连接 → `未连接 MIDI 键盘`（不支持 / 授权被拒 / 连接失败照实说原因）；音轨有内容时也提示（没键盘就录不了也放不了） |

## 2. 关键决策

- **D1 触发只看 Note On，不看踏板**：需求口径是"按键盘**任意键**"。单独踩踏板不开始录制
  （踏板事件在录制中仍算输入，见 D3）——"按键"才是开始演奏的信号。
- **D2「未播放也未录制」= `mode === 'idle'`，不要求音轨为空**：与主设计 D2 的覆盖录制口径一致——
  「重录一段 = 把线拖到那段起点、直接弹」，录制线扫过的旧内容照常被抹掉。音轨有没有内容只影响
  空音轨提示（R6），不影响能不能自动开录——R6 的"未曾录制"只限定**提示**的显示，不是自动录制的开关：
  自动暂停之后音轨已有内容，再演奏当然要接着录（否则"录一段、停一下、再录一段"就断了）。
  - **已知取舍**：回放暂停后也处在 `idle`，此时按键会从暂停处开始一次覆盖录制（线扫过的旧内容被抹掉，
    本工具没有撤销）。这是"未播放也未录制即自动开录"的字面口径；若要区分"回放暂停"与"空闲"，
    得给走带再加一维来源状态——本文档按需求原话不引入，实际用起来别扭再单开一版设计。
  - **拖动音轨期间不自动开录**（与主设计 D4「拖动期间不录制」同一口径）：拖动中收到 Note On
    只回送、不录制，也不开始录制；松手后按键照常自动开始。
  - 回放中（`mode === 'playing'`）按键不开始录制：需求限定"未播放也未录制"。
- **D3 静默判定 = 连续 3 秒既没有按键/踏板事件，且手上没有按住的键、脚下没有踩住的踏板**：
  - Note On/Off 与 CC64/66/67 都刷新计时基准 `lastInputAt`：踩踏板也是演奏动作，且踩下的区间
    本身就是要录下来的内容（否则"最后一个音 + 延音"的收尾会被切掉）；
  - `held.size > 0`（按着键）或 `pedalDown.size > 0`（踩着踏板）时**不计时**：长按的音、踩着不放的
    延音都要录到松开为止，否则一个 5 秒长音会被自动暂停切成 3 秒；
  - 计时基准取**时间轴位置**（`position`）而不是墙钟：3 秒就是录制线走过 3 秒，与计时器、拖动挂起
    天然一致（拖动期间时钟停走，不会因为"拖着看了 10 秒"而一松手就自动暂停——`endScrub` 还会把
    基准重置到松手处）。
- **D4 看门狗挂在既有的 25ms 调度定时器上**（`syncTicker()`）：不新增 `setTimeout`，`RecorderHost`
  注入接口保持 `now/setInterval/clearInterval` 三个方法不变（测试用假时钟照旧）；定时器只在
  "回放（要 lookahead 排期）或自动录制（要看守静默超时）"时运行，空闲与手动录制不空转。
- **D5 提示走 DOM 浮层，不画进画布**：与按钮 Tips 同一层（`.recorder__stage` 内的绝对定位元素），
  可访问（`role="status"`）、可被浏览器冒烟直接断言（画布上的文字没法断言）；`pointer-events: none`
  保证拖动音轨的手势照常落到画布上。画布仍只画音符 / 网格 / 录制播放线。
  主设计 §3.4 里"音轨内不画任何说明文字"的旧口径由 R6 修订为该条的本意——
  "提示只出现在控件层"，现在控件层多了这一处**只有全空音轨才出现**的中央提示。
- **D6 中央提示是"一句话状态位"**：音轨正中央只有一处提示浮层，按状态决定说什么（`centerHintText()`，
  没话可说就隐藏）——
  1. 未连接 MIDI 键盘 → 「未连接 MIDI 键盘」（音轨有内容时也说：没键盘就录不了也放不了）；
     浏览器不支持 / 授权被拒 / 连接失败沿用按钮 Tips 那套具体原因（`midiHintText(status, fallback)`，
     只把"确实没连上"这一类的用词从祈使句「请先连接 MIDI 键盘」换成陈述句「未连接 MIDI 键盘」）；
  2. 已连接 + 未播放未录制 + 全空音轨 → 「在 MIDI 键盘上演奏可自动开始录制」（R6）；
  3. 其余（播放中 / 录制中 / 有内容且空闲）→ 不提示。
     `idle`/`connecting` 两个瞬时态不提示：那时还没有结论，免得每次进页闪一下（连接挂起时由按钮
     Tips 与运输栏的连接提示负责，见研究文档 `20260906-web-midi-connect-hang.md`）。
     提示字号取面板标题档 `--fs-panel`（17.5px，2026-09-13 用户口径"调大一点"，此前是正文档 11.4px）。
- **D7 提示没有描边，底色是"音轨底色 → 透明"的渐隐**（2026-09-13 用户口径：不要有色边框）：
  不用面板/气泡那套"实底色 + 发丝描边"（那是 Tips / 弹层的语言，摆在音轨正中央像贴了块牌子），
  改为无描边的径向渐变——中心近乎不透明地盖住网格与播放线、四周渐隐到全透明，再配 `--r-lg` 圆角，
  整体融进音轨底色（取画布渐变中段的 `#161513` 一带）。

## 3. 实现

### 3.1 控制器（src/core/recorder.ts）

新增状态（都是私有字段，不进 `RecorderUiState`——视图不需要知道录制是谁开始的）：

| 字段                  | 含义                                                                  |
| --------------------- | --------------------------------------------------------------------- |
| `autoRecord: boolean` | 本次录制是否由演奏自动开启（自动录制才走静默看门狗）                  |
| `lastInputAt: number` | 最近一次按键/踏板输入的时间轴时刻（秒）：静默计时基准                 |
| `scrubbing: boolean`  | 音轨拖动中（`beginScrub` → `endScrub`）：拖动期间不自动开始录制（D2） |

接口与行为：

| 位置                      | 行为                                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `onNote`（Note On）       | 回送之后、录制判定之前调用 `startAutoRecording()`：空闲且未拖动时 `startRecording(true)`，随后这一次按下照常进入 `held`（成为第一个音符）                    |
| `startAutoRecording()`    | 私有：`disposed / scrubbing / mode !== 'idle' / 未连接` 任一成立就返回（只由 Note On 调用）                                                                  |
| `startRecording(auto)`    | 私有：`toggleRecord()`（手动，`auto = false`）与自动开始共用的开始路径——置模式、清 held、`beginPass`、起表、`syncTicker()`、`emitState()`                    |
| `checkAutoPause()`        | 私有：静默看门狗（D3）。命中即 `finishRecording()`——与手动暂停完全相同：按住的键与未抬起的踏板就地收尾、`commitPass` 落定擦除、位置停在超时处、模式回 `idle` |
| `finishRecording()`       | 收尾时清 `autoRecord`（下一次录制重新判定来源）                                                                                                              |
| `syncTicker()`            | 私有：按 `running && (playing \|\| (recording && autoRecord))` 启停定时器（D4）                                                                              |
| `tick()`                  | 定时器回调改为分发：`playing` → `tickPlayback()`（原 lookahead 逻辑）、`recording` → `checkAutoPause()`                                                      |
| `beginScrub()/endScrub()` | 置/清 `scrubbing`；拖动结束时把 `lastInputAt` 重置到松手位置（拖动耗时不记入静默）                                                                           |

`togglePlay()`、`clear()`、`restore()`、`onMidiStatus()`（拔出自动暂停）、回放到末尾自动暂停等既有
路径保持原语义，只把 `startTicker()/stopTicker()` 换成 `syncTicker()`。自动开始的录制被手动暂停、
被拖动打断、被断开打断，都沿用这些既有路径（R4）。

### 3.2 视图（src/ui/recorder-view.ts）

- 构造函数里创建 `.recorder__hint`（`role="status"`、初始 `hidden`）插进 `.recorder__stage`；
- `centerHintText(state)`（导出，纯函数、有单测）决定"说什么 / 显不显示"，`setState()` 里
  `textContent` + `hidden` 一起更新（文案没变就不碰 DOM）：
  | 状态                                                        | 中央提示                             |
  | ----------------------------------------------------------- | ------------------------------------ |
  | 未连接（`no-devices` / `unsupported` / `denied` / `error`） | `未连接 MIDI 键盘`（失败原因照实说） |
  | `idle` / `connecting`（连接还没结论）                       | 不显示                               |
  | 已连接 + `mode === 'idle'` + `!hasContent`                  | `在 MIDI 键盘上演奏可自动开始录制`   |
  | 已连接 + 播放中 / 录制中 / 有内容                           | 不显示                               |
- 「全空」的判据用既有的 `hasContent`（音符 / 踏板 / 按住的键任一非空即算有内容，见主设计 R17 与
  `20260913-recorder-pedals.md` D6）；
- `midiHintText(status, fallback)` 多了一个默认参数：按钮 Tips 保持「请先连接 MIDI 键盘」，
  中央提示传「未连接 MIDI 键盘」，其余（不支持 / 被拒 / 失败）两处共用同一句话，避免两份文案漂移；
- CSS（`src/style.css` 的 `.recorder__hint`）：绝对定位居中（`left/top: 50%` + `translate(-50%, -50%)`）、
  字号 `--fs-panel`（17.5px）、**无描边**——底色是"音轨底色（`rgba(22, 21, 20, …)`，画布渐变中段的
  `#161513` 一带）→ 全透明"的径向渐变（中心 0.94、45% 处 0.88、边缘 0），配 `--r-lg` 圆角，
  所以它是一团融进音轨的暗晕而不是贴上去的色板；`pointer-events: none` 让拖动音轨的手势照常落到画布上；
- 录制按钮的图标切换（R5）不需要新代码：`setState()` 早已按 `mode === 'recording'` 换成 ⏸ 并加
  `is-recording` 呼吸光圈，自动录制只是让 `mode` 变成 `recording` 的另一条路径。

## 4. 非目标

- 不做自动录制的开关 / 偏好设置（空闲时演奏即录就是需求口径）；
- 不做静默倒计时提示、不做"已自动暂停"的通知胶囊（图标回到 ●、计时器停住即为反馈）；
- 不改手动录制的语义（多长的静默都继续录，只能手动暂停）；
- 不做"踏板单独踩下也开始录制"（D1），也不按 CC64/66/67 之外的 CC 判定静默；
- 不改走带模型、覆盖录制（punch-in）、踏板与导出（`20260912` / `20260913-recorder-pedals` 的设计照旧）。

## 5. 验证

- 单元测试：`src/core/recorder.test.ts` 的「演奏自动录制」一组——
  空闲按键即开录（第一个音符就是这次按下、状态回调为 `recording`）、单独踩踏板不触发、
  静默 3 秒自动暂停（2.9s 不暂停 / 3.1s 暂停、位置停在超时处、定时器停掉）、自动暂停后再次演奏
  从暂停处继续、手动录制静默 5 秒仍在录、自动录制可手动暂停、按住键 / 踩着踏板不触发自动暂停
  （长音录到松开为止）、回放中按键不录、拖动期间按键不开录（松手后照常）、自动录制中拖动后重新计时、
  键盘拔出收尾；`src/ui/recorder-view.test.ts` 的 `centerHintText` 一组——全空空闲提示"演奏即录"、
  有内容 / 播放中 / 录制中不提示、未连接提示「未连接 MIDI 键盘」（有内容也提示）、不支持 / 被拒 /
  失败照实说原因、`idle`/`connecting` 不提示，以及 `midiHintText` 的 fallback 用词；
- 浏览器冒烟：`scripts/probe-recorder.mjs`——全空音轨中央提示（文案逐字 + 字号 ≥16px + 居中偏差 ≤2px +
  无描边 / 渐隐到透明的渐变底色 / 圆角，见 D7）、
  按键自动开录（按钮变暂停、提示收起）、静默 3 秒自动暂停（图标回录制、计时器停住）、再次演奏从暂停处
  继续、录过内容暂停后提示不再显示、手动录制静默 3.6 秒仍在录、清空后提示重现；未连接时中央提示
  「未连接 MIDI 键盘」（无设备 / 拔出键盘两处，含"有内容也提示"），插上键盘后换回"演奏即录"；
- 全量校验：`pnpm format:check` / `pnpm typecheck` / `pnpm lint` / `pnpm test` / `pnpm build`。
