# 研究：Web MIDI 的按键力度与踏板信息获取（含“踏板幅度”可检测性）

- 日期：2026-09-12
- 状态：**调查结论**（支撑设计草案 `docs/development/design/20260912-midi-debug-velocity-pedal.draft1.md`）
- 参考：`docs/development/reference/midi/webmidi-api.md`、`docs/development/reference/midi/format-and-libraries.md`
- 外部资料获取日期：2026-09-12

## 1. 问题

「MIDI 键盘」调试工具要增加两类信息：

1. **按键力度**（Note On 的 velocity）——希望显示数值，并映射到视觉强度；
2. **踏板信息**——希望显示踏板状态；若设备**支持踏板幅度（踏板角度 / 半踏板）**则显示幅度数值，
   否则退化为三盏“踩下即亮”的指示灯。

因此需要回答三个问题：

- Q1：力度消息本身如何取得？现有解析层丢弃了什么？
- Q2：踏板消息如何取得？哪些控制器号对应“三个踏板”？
- Q3：**能否判断设备是否支持踏板幅度？** 支持时数值从哪来？

## 2. Q1 力度：消息层完全可得，现有代码已解析但未使用

MIDI 1.0 的 Note On（状态字节 `1001nnnn`）第二数据字节即 velocity（0–127），
现有 `parseMidiMessage`（`src/core/midi/input.ts`）已经把它解出并放进 `MidiNoteEvent.velocity`，
只是调试页过去只用它作“按住与否”的布尔量。**力度无需新增任何接入能力，纯属渲染层缺口。**

参考（MIDI 1.0 消息概要，<https://midi.org/summary-of-midi-1-0-messages>）：

> `1001nnnn` / `0kkkkkkk` `0vvvvvvv` — Note On event. This message is sent when a note is depressed
> (start). (kkkkkkk) is the key (note) number. (vvvvvvv) is the velocity.

### 2.1 力度与音量的关系：接近平方律（不是线性）

MIDI 力度（0–127）**不是**音量本身，它与峰值幅度近似成**平方关系**。Csound 的 `ampmidid`
opcode 按 Roger Dannenberg《The Interpretation of MIDI Velocity》(ICMC 2006) 给出的映射为：

> `a = (m·v + b)²`，其中 `a` = 幅度、`v` = MIDI 力度、`b = 127/(126·√r) − 1/126`、
> `m = (1 − b)/127`、`r = 10^(R/20)`、`R` = 指定动态范围（dB）。
> 即“力度 1 对应动态范围最低端、力度 127 对应 0 dB”，中间按平方律插值。
> 来源：<https://csound.com/manual/opcodes/ampmidid/>（引 Dannenberg, ICMC 2006）

**对本项目的意义**：人耳对响度的感知本身也是压缩的（对数/幂律），因此
“响度 ≈ 力度²”这一关系意味着**力度线性映射到视觉亮度是错的**——
线性下 v=1 与 v=30 的视觉强度只差 0.23、肉眼几乎不可辨，而这两个力度对应的实际响度
差了约 30 dB（感知上差别巨大）。视觉强度应取该关系的**感知逆曲线**（开方方向）：
`I(v) = (v/127)^0.4`，低力度区间被拉开、高力度区间被压缩，与听感一致。
（设计侧落地见 `docs/development/design/20260912-midi-debug-velocity-pedal.md` §4.1。）

## 3. Q2 踏板：CC 消息 + 固定控制器号

踏板是 **Control Change**（状态字节 `1011nnnn`，即 `0xBn`，data1 = 控制器号 0–119，
data2 = 值 0–127）。三个钢琴踏板对应的控制器号（MIDI 1.0 规定，与厂商无关）：

| CC 号 | 名称（PG Music《MIDI Controller Numbers》附录原文）         | 钢琴上的踏板       |
| ----- | ----------------------------------------------------------- | ------------------ |
| 64    | Damper Pedal (Sustain) `[Data Byte of 0-63=Off, 64-127=On]` | 延音踏板（右）     |
| 66    | Sostenuto                                                   | 选择延音踏板（中） |
| 67    | Soft Pedal                                                  | 弱音踏板（左）     |

来源：<https://www.pgmusic.com/manuals/rb2021full/appendixC.htm>（MIDI 1.0 控制器号附录）。
注：CC65（Portamento）**不是**钢琴踏板，不应纳入三踏板指示；CC4（Foot Controller）是外接表情踏板，
语义随设备而变，同样不纳入。

### 3.1 关于“数值方向”的既有约定

同一份资料明确写出延音踏板的判读阈值：**0–63 = Off，64–127 = On**。
本项目已有实现与之一致：`src/core/midi/quantize.ts` 的 `buildSustainIntervals()` 亦以 `e.value >= 64`
作为“踩下”。新的踏板 UI 必须沿用同一阈值，避免两处语义分叉。

### 3.2 幅度数值本身也在消息里

CC 的 data2 是 7 位值（0–127），**任何** CC 消息都天然携带一个 0–127 的值——
“踏板幅度”并不需要额外消息类型，它就藏在 CC64/66/67 的 data2 里。
问题不在“能不能收到数值”，而在“设备会不会发出 0/127 之外的中间值”。

## 4. Q3 可检测性：Web MIDI 不提供设备能力，只能“观察流量”判定

### 4.1 规范层面没有能力查询接口

Web MIDI API 的设备描述只有端口元数据（`id` / `manufacturer` / `name` / `version` / `type` /
`state` / `connection`），**没有任何“本设备支持哪些控制器 / 是否支持半踏板”的字段**
（见参考文档 `webmidi-api.md` §2、§5.1；MIDI 设备能力在传统上是靠厂商的 _MIDI Implementation Chart_
纸质/PDF 文档声明的，不在协议里）。因此“是否支持踏板幅度”**不可能**通过一次 API 调用问出来。

结论：只能**观察消息流**——统计每个踏板 CC 是否出现过 0/127 之外的值。
这是唯一在浏览器侧可行、且与设备无关的判据；判据本身是确定性的（不是猜测）：
设备发出中间值的**必要前提**是它具备连续踏板硬件。

### 4.2 常见设备的实际行为（用于确定判据）

- **开关式踏板**（最常见的便携键盘附赠踏板、第三方单极性开关踏板）：只有通断两态，
  键盘固件只发 `0` / `127`（部分设备发 `0` / `64` 或 `0` / `100` 之类的固定两值）。
- **连续式踏板**（如带半踏板功能的数码钢琴原厂踏板）：随踩下深度连续发送，
  典型为 0–127 的一段区间（并非每个值都出现，取决于采样率/扫描精度，常见十几个到几十个不同值）。
- 因此判据可以写成：**同一踏板 CC 上出现过任一落在 (0, 127) 开区间内的值 → 该踏板支持幅度表达**。
  - 只收到 `0` / `127` 之类端点值 → 该踏板按开关式显示指示灯；
  - 阈值 `value >= 64` 的判读仍然成立（开关式与连续式共用）。

> 说明：“出现过中间值”是**充分**判据（能证明支持幅度）；只见过端点值**不能反证**不支持
> （可能只是用户没有半踩）。所以指示灯模式在 UI 上应表述为“未观察到幅度值”，而不是
> “设备不支持”——这是本方案对用户唯一需要澄清的语义点。

## 5. 对本项目的技术结论

| 结论 | 内容                                                                                                                      |
| ---- | ------------------------------------------------------------------------------------------------------------------------- |
| C1   | 力度（velocity 0–127）已在 `MidiNoteEvent` 中，直接在渲染层使用即可，零接入改动                                           |
| C2   | 踏板是 CC（`0xBn`），解析层目前一律返回 `null`（`input.ts` 第 36 行），需要新增一条 CC 事件分支                           |
| C3   | 三踏板 = CC64 / CC66 / CC67；判读阈值 `>= 64` 为踩下（与 MIDI 1.0 附录及本项目 `quantize.ts` 一致）                       |
| C4   | 幅度（踏板角度）就是 CC 的 data2；“是否支持”只能由**观察到的值域**推断，规范无可查询能力                                  |
| C5   | 判据：某踏板出现过 0/127 以外的中间值 → 该踏板显示幅度方块与数值；否则显示指示灯                                          |
| C6   | 从首次观察到中间值起应**锁定**为幅度模式（本次会话），否则踏板回到 0/127 时 UI 会在两种形态间抖动                         |
| C7   | 解析层改动影响 `MidiConnection`（`core/midi/connection.ts` 唯一消费方）与调试页；练习模式只关心 Note 事件，需保证行为不变 |

## 6. 未决 / 需用户确认

1. 力度的视觉映射细节（线性）——见设计草案 §4.1 与其中的待确认项；
2. 调试页是否迁移到共享的 `MidiConnection`（当前仍自持 `requestMIDIAccess` 流程）——见设计草案 §3.3；
3. 指示灯在 0–127 全量值域上的“中间态”表述（幅度模式下的方块是否同时兼作指示灯）。
